# 📖 Baremetal 从核任务流程 — 状态机、中断、看门狗与实时响应

> **处理器分配**：Cortex-A72 Core 1 (裸机运行态，无 OS 调度干扰)  
> **代码模块**：`Baremetal_Slave_Node/src/slaver_00_example.c`  
> **核心特征**：硬实时响应、亚毫秒级物理告警与硬件看门狗自愈

---

## 1. 从核 Baremetal 初始化流程

Linux 侧通过 remoteproc 加载并启动从核 ELF；从核侧完成 OpenAMP 资源表、共享内存和 RPMsg 端点初始化。随后从核执行以下底层寄存器级初始化流程：

```
                [ 从核 Core 1 物理唤醒 ]
                          │
                          ▼
             [ 金属硬件层初始化 metal_init ]
                          │
                          ▼
         [ 板级总线驱动加载 EXTI & I2C & GPIO ]
                          │
                          ▼
        [ remoteproc 从域初始化 & 共享内存映射 ]
                          │
                          ▼
          [ FWDT0 硬件看门狗配置 (10秒超时) ]
                          │
                          ▼
            [ 注册 RPMsg 通道端点 ept ]
                          │
                          ▼
        [ 进入无限轮询主循环 FRpmsgEchoApp() ]
```

1.  **硬件层初始化 (`metal_init`)**：加载 libmetal 用户态硬件抽象库，映射共享内存物理区域。
2.  **物理外设配置**：调用 `Buzzer_Init()`、`Fire_Sensor_Intr_Init()` 等函数配置引脚复用与方向。
3.  **看门狗准备**：通过 `FWdtLookupConfig(FWDT0_ID)` 查表并初始化看门狗，预设复位溢出时间为 10 秒。
4.  **建立端点**：注册端点回调 `rpmsg_endpoint_cb`，进入信道战备状态。

## 2. 裸机主循环与状态机逻辑

从核主循环利用 `remoteproc_resource_init` 和极速轮询机制来运转。系统的业务逻辑可抽象为一个严密的“状态机”：

```
     ┌────────────────────────────────────────────────────────┐
     │                       BOOT 状态                        │
     └──────────────────────────┬─────────────────────────────┘
                                │
                                ▼
     ┌────────────────────────────────────────────────────────┐
     │                HANDSHAKE_WAIT (等待握手)               │
     │      - 持续查询共享内存, 报警输出保持关闭，等待主核首个心跳。│
     └──────────────────────────┬─────────────────────────────┘
                                │ 收到主核首个 RPMsg 心跳包
                                ▼
     ┌────────────────────────────────────────────────────────┐
     │                NORMAL_MONITOR (正常监测)               │
     │      - 500ms 滴答计数器递增; 正常喂狗 FWdtRefresh     │
     │      - 周期性物理读取 AHT20 温湿度                    │
     └──────────────────────────┬─────────────────────────────┘
                                │ 连续 10 次未恢复（约 5 秒）
                                ▼
     ┌────────────────────────────────────────────────────────┐
     │                FAIL_SAFE_ACTIVE (失效安全)             │
     │      - 物理蜂鸣器长鸣; 打印 ALERT 日志                 │
     │      - 将看门狗超时调整为 1 秒并停止喂狗，触发整板冷复位。 │
     └────────────────────────────────────────────────────────┘
```

*   **HANDSHAKE_WAIT 状态**：在此状态下，看门狗尚未启动（防启动即死锁），等待主核拉起 Qt 应用。
*   **NORMAL_MONITOR 状态**：收到首包消息后启动看门狗。从核通过接收回调更新 `g_heartbeat_miss_count = 0`。
*   **FAIL_SAFE_ACTIVE 状态**：主从核以 500ms 周期进行心跳检查；连续 10 次未恢复（约 5 秒）后进入 Fail-Safe。从核将看门狗超时调整为 1 秒并停止喂狗，触发整板冷复位。为避免板上外设异常，蜂鸣器直接鸣响报警。

## 3. GPIO EXTI 硬件中断接管与响应时效

### 火焰告警的独立硬实时路径  
火焰传感器信号接入从核 GPIO EXTI 高优先级中断；中断触发后，从核 Bare-metal 直接执行本地报警仲裁，并通过 GPIO 驱动蜂鸣器输出。该路径不依赖 Linux 调度、主程序或跨核通信。  

示波器实测：从传感器触发信号到蜂鸣器 GPIO 报警输出，端到端延迟为 **626μs**，实现亚毫秒级物理告警响应。  

测试口径：CH1 为传感器触发输入，CH2 为蜂鸣器/GPIO 报警输出，时间差为 626μs。

## 4. FWDT0 底层硬件看门狗与冷重启

看门狗 `FWDT` 是本系统防跑飞与实现崩溃自愈的核心硬件屏障。

### 4.1 驱动接口集成
在 Standalone 开发框架下，从核调用飞腾官方硬件驱动 API 控制看门狗：
*   **加载句柄**：`FWdtLookupConfig(FWDT0_ID)` 获取看门狗 `FWDT0` 寄存器物理基地址。
*   **使能看门狗**：`FWdtStart(&g_wdt_ctrl)` 写入控制寄存器，硬件看门狗开始倒计时。
*   **定时刷新 (喂狗)**：`FWdtRefresh(&g_wdt_ctrl)` 将递减计数器重新置为满值。

### 4.2 硬件冷重启 (Cold Reset) 路径
1.  正常情况下，从核主循环每隔一定周期，在确认主核心跳健康时调用 `FWdtRefresh()`。
2.  当主核崩溃后，从核执行 `g_fail_safe_active = true;` 锁死控制，故意忽略后续的喂狗指令。
3.  看门狗内部计数器递减至 0。
4.  看门狗控制器向飞腾芯片复位管理器 (Reset Manager) 发出硬复位信号。
5.  SoC 硬件执行 Cold Reset，整机断电复位重置。

## 5. 声光报警与异构物理联动仲裁

从核承担着物理报警的“终极仲裁权”，保障在任何软件异常场景下，报警逻辑仍能正确运转。

在主循环中，从核不断执行仲裁函数 `Execute_Alarm_Arbitration()`：
```c
void Execute_Alarm_Arbitration(void) {
    // 1. 读取底层物理火焰传感器状态（低电平代表有火灾告警）
    int sensor_level = Fire_Sensor_Read_Level();
    
    // 2. 结合物理触发与主核下发的 AI 违规请求执行“逻辑或”仲裁
    if ((sensor_level == 0) || flag_ai_alarm_req) {
        Buzzer_Set(1); // 驱动蜂鸣器进行本地物理报警
    } else {
        Buzzer_Set(0); // 关闭报警输出
    }
}
```

*   **物理独立触发**：若 Linux 主核崩溃导致 `flag_ai_alarm_req` 丢失，此时一旦传感器端监测到火灾（`sensor_level == 0`），从核仍能瞬间开启蜂鸣器。这一架构完全摆脱了对主核操作系统的通信依赖。

## 6. 核心结论

通过 Bare-metal 从核、EXTI 硬件中断与 GPIO 直控路径，系统在主核 Linux 负载异常或失联时，仍可独立完成火焰险情的本地物理报警；示波器实测端到端响应延迟为 **626μs**。
