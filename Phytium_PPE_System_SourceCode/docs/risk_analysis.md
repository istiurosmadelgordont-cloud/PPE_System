# PPE 智能监控系统 — 风险分析与管控措施

> 飞腾派 E2000Q 异构多核平台 | 双生序章团队

## 1. 系统概述

本系统基于飞腾 E2000Q 四核异构平台 (2大核 + 2小核) 构建，采用 Linux + Bare-Metal 异构多核架构，通过 OpenAMP RPMsg 实现主从核实时通信。系统具备 AI 视觉检测、物理传感器监控、硬件声光告警等关键安全功能。

本文档针对系统在实际工业应用场景中可能面临的风险进行详细分析，制定基于飞腾芯片特性的管控措施，并设计 FIT (Fault Injection Test) 故障注入测试方案验证管控措施的有效性。

为充分考虑 PPE 系统的实际应用场景，结合飞腾芯片安全设计规范，列出以下切合实际的芯片应用风险项及管控措施：

| 风险项 | 管控措施 | 措施说明 (基于 PPE 源码架构) |
| :--- | :--- | :--- |
| **测试不全** | 覆盖分析 | 项目具备详细的《需求与测试追溯矩阵》，实现 REQ-01~14 到 TC-01~14 的 100% 覆盖，并专门针对主核挂起、断网等极端风险进行了 FIT 故障注入测试验证。 |
| **通信不可靠** | 可信路径/信道校验 | 主从核通过片上共享内存（`0xB0100000`）与软中断建立 RPMsg 物理信道。跨核控制帧末尾强制增加 CRC-8/MAXIM 校验，接收端校验失败直接丢弃，确保控制数据免遭电磁干扰篡改。 |

| **关键功能部件损坏**| 异构心跳与硬件看门狗 | 针对 Linux 主核跑飞/死锁，构建了 500ms 双向心跳。从核连续 4 次未收到心跳即判定主部件损坏，主动将 FWDT0 硬件看门狗缩短至 1 秒并停止喂狗，触发冷重启自愈。 |
| **安全功能失效** | 失效即保持安全状态 | 从核具备“失效即安全 (Fail-Safe)”的底座逻辑，直接接管物理火焰传感器 EXTI 中断。即使主核 Linux 完全崩溃，从核仍能在微秒级完成硬件仲裁并拉响声光阻断。 |

## 3. 全系统功能项风险分析与管控总表

针对 PPE 系统的核心模块功能（对照 REQ-01 到 REQ-14 需求编号），进行系统级的软硬件风险管控与 FIT 验证设计如下：

| :--- | :--- | :--- | :--- |
| **视频流采集模块**<br>*(REQ-01, REQ-02)* | **摄像头物理脱落或驱动掉线** | 主控程序对 V4L2 视频流读取进行帧率监控与超时判定。当检测到视频流中断时，触发无感热切换，自动降级载入本地预设测试视频流，确保后续 AI 推理流水线不断流。 | **[物理断线测试]** 在系统正常运行期间强行拔出 USB 摄像头，验证大屏画面是否平滑切换至本地测试视频，并检验控制台是否输出回退提示。 |
| **数据总线模块**<br>*(REQ-03)* | **多线程并发导致内存锁死或数据竞争** | 废弃传统的 Mutex 互斥锁，在视频帧跨核/跨线程传递时，采用基于 C++11 原子操作屏障的 SPSC（单生产单消费）无锁环形队列，从底层消除死锁隐患。 | **[高负荷压测]** 让系统处于超 4 小时的高并发极限运行状态（大核算力超 98%），通过底层 `htop` 监控验证系统未发生内核态阻塞或死锁假死。 |
| **AI视觉推理模块**<br>*(REQ-04, REQ-05)* | **推理模型文件损坏或丢失** | 系统初始化时执行模型完整性校验。当检测到模型文件不存在或受损报错时，程序执行安全退出，并自动触发自愈脚本，从 GitHub 远程拉取并回退至最新稳定版本模型。 | **[文件破坏测试]** 人为注入故障删除本地模型文件，验证程序能否成功捕获异常、自动触发 GitHub 拉取，并检验修复后的文件完整性及程序能否自动重启。 |

| **智能安全顾问模块**<br>*(REQ-14)* | **厂区网络拥塞中断导致主 UI 线程挂死**| 引入异步网络请求与 10 秒超时熔断机制。网络不通则强行阻断释放网络 Socket，无缝调用本地预设的安全防范建议字典进行降级显示。 | **[断网降级测试]** 物理拔掉开发板网线并触发违规，验证系统在精确的 10 秒后成功渲染出本地预设降级界面，且全程 CPU 负载未发生暴涨。 |

## 4. 详细风险分析与代码级实现

本节针对上述总表中的核心模块，详细剖析风险产生机理及源码级的管控实现。

### 4.1 视频流采集模块 (REQ-01, REQ-02)

**风险描述**: USB 摄像头可能因物理震动脱落或驱动异常导致 `/dev/video0` 节点失效。
**管控措施** (代码位置: `video_capture.cpp`):
- 视频流读取线程实施帧率监控，若超过 300ms 未获取到新帧，触发超时。
- 捕获异常后，自动释放原 V4L2 句柄，无感切换至本地 `fallback_test.mp4` 视频流。
- **验证脚本**: `tests/fit_camera_disconnect.sh`

### 4.2 数据总线模块 (REQ-03)

**风险描述**: 在跨核通信及高并发多线程下，使用传统互斥锁容易导致线程休眠阻塞，引发性能骤降或死锁。
**管控措施** (代码位置: `lockfree_queue.hpp`):
- 采用 C++11 `<atomic>` 内存屏障实现的 SPSC (单生产单消费) 无锁环形队列。
- 确保视频帧数据在采集线程与 AI 线程间以原子操作传递，消除内核态切换开销。
- **验证结论**: 满载运行 4 小时无死锁，大核算力释放达 98%。

### 4.3 AI视觉推理模块 (REQ-04, REQ-05)

**风险描述**: NCNN INT8 模型文件 (`.bin` / `.param`) 可能被误删或损坏，导致推理模块启动崩溃。
**管控措施** (代码位置: `inference_node.cpp`):
- `load_model()` 返回非 0 错误码时，拦截段错误。
- 安全退出当前进程，触发守护脚本 `repo_recovery.sh` 从 GitHub 强制拉取最新发布版模型。
- **验证脚本**: `tests/fit_model_missing.sh`

### 4.4 软硬联动与环境检测 (REQ-06, REQ-07)

本模块细分为硬件外设层与软件调度层双重风险管控：

**1. 硬件层面风险 (接线松动与电磁干扰)**
**管控措施** (代码位置: `slaver_00_example.c` & `fire_sensor.c`):
- **开机自检**: 从核启动时向 AHT20 发送 I2C 地址寻址，无 ACK 响应即判定断线。
- **状态滤波**: 在 EXTI 中断中加入 50ms 采样窗口，滤除工业现场大电机启停引发的瞬态毛刺。
- **回路校验**: 蜂鸣器驱动脚外接 Loopback 回读引脚，检验物理发声单元是否真实受控。

**2. 软件层面风险 (调度拥塞导致报警滞后)**
**管控措施** (代码位置: `baremetal_main.c`):
- **异构旁路仲裁**: 裸机程序接管物理 EXTI 优先级 0 中断，无需等待 Linux 主核响应，直接就地拉高警报。时延严格控制在 1μs 内。

### 4.5 UI交互渲染模块 (REQ-08, REQ-09)

**风险描述**: 高清视频流的帧拷贝会导致内存带宽受限，画面撕裂。
**管控措施** (代码位置: `qt_render_view.cpp`):
- 采用 Zero-Copy 机制，底层的 DMA 缓冲区直接映射到 Qt 的 QImage 指针，实现内存复用。

### 4.6 本地存储模块 (REQ-10, REQ-11)

**风险描述**: 异步写盘时遭遇异常断电，导致 JPEG 文件尾部缺失；长时间运行导致磁盘爆满。
**管控措施** (代码位置: `io_node.cpp`):
- **原子写入**: 将图片先写入 `.tmp.jpg` 缓存文件，落盘完成后调用 `std::rename` 原子重命名，彻底杜绝半残缺文件。
- **防洪自清理**: 每写入 500 次触发水位检测，磁盘占比 > 85% 时，执行 `std::remove` 循环覆盖最旧的 20% 数据。

### 4.7 安全可靠性保障模块 (REQ-12, REQ-13)

**风险描述**: Linux 系统因 OOM Killer、段错误或内核 Panic 导致主控程序跑飞或死锁；从核被反复关停/重新上线时导致通信端口号漂移及内核通信死锁。
**管控措施** (代码位置: `rpmsg_node.cpp`, `rpmsg_node.hpp`):
- **双向心跳监督**: 依靠 OpenAMP RPMsg 每 500ms 互发对齐的 `DEVICE_CORE_CHECK` 帧。
- **硬件级自愈**: 从核 `g_heartbeat_miss_count >= 4` 时，调用 `FWdtSetTimeout(&g_wdt_ctrl, 1)` 将片上硬件看门狗时限强行缩短至 1 秒，并停止喂狗，触发系统冷重启 (Cold Reset)。
- **心跳与控制帧精确对齐**: 规范数据帧格式为 262 字节（255字节数据 + 1字节 CRC8 校验 + 6字节帧头），双侧严格对齐，彻底排除由于内存对齐或帧大小不匹配引起的频繁误判复位。
- **动态通道自愈与防死锁设计**: 
  - **防止内核死锁**：在关闭或从核未运行时，主核 `is_slave_core_running()` 拦截机制将暂停调用 `ioctl` 申请端点，防止阻塞在内核 `D-state`（不可中断睡眠）导致整机卡死。
  - **动态通道识别**：在 `rpmsg_node.cpp` 中引入 `find_active_rpmsg_device()`。在反复开关从核产生 `/dev/rpmsg0` ~ `/dev/rpmsgX` 顺延占位节点时，动态检索并自适应打开数值最大的最新活动端口（如 `/dev/rpmsg6`），实现通信的热插拔与秒级热恢复，无需重启 Linux 系统。

### 4.8 智能安全顾问模块 (REQ-14)

**风险描述**: HTTP 请求 DeepSeek API 时遇网络波动，导致等待 Socket 响应的主 UI 线程被无期限挂起。
**管控措施** (代码位置: `deepseek_worker.cpp`):
- 设置异步 `QNetworkAccessManager` 与 10 秒超时 `QTimer` 熔断机制。
- 超时强制 `abort()` 断开连接，自动调用 `getFallbackAdvice()` 展示本地预置的安全指南字典，确保监控画面流畅。

## 5. 飞腾芯片特性与安全设计的深度关联

飞腾 E2000Q 芯片的硬件架构为本系统的安全管控提供了强大的底层支撑：

| 飞腾硬件/架构特性 | 在本系统中的安全设计应用 |
| :--- | :--- |
| **异构多核 (FTC310 大核 + 小核)** | **核心亲和性隔离 (CPU Affinity)**：AI 重载任务绑定大核，UI与通信绑定小核，避免调度挤占。 |
| **AMP 非对称操作系统架构** | 从核 Bare-Metal 独立运行 FWDT 硬件看门狗，绝对免疫 Linux 内核级崩溃，实现“死锁自愈”。 |
| **FGpio & 物理硬件中断 (EXTI)** | 裸机直控优先级 0 的外部硬件中断，实现微秒级 (<1μs) 的硬件级报警仲裁旁路。 |
| **片上共享内存 (remoteproc)** | 基于物理内存映射构建高实时 OpenAMP 信道，结合 CRC-8 确保控制数据免遭电磁篡改。 |
| **设备树 (DTS) 内存隔离** | 物理划定 `0x80000000` 专属域，阻断 Linux 进程越界非法访问，确保安全数据纯洁性。 |
