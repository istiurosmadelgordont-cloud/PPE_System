## 2. 异构多核关键功能风险管理闭环设计 (7.2)

### 2.1 应对【主控程序跑飞】：主从心跳与看门狗重启 (7.2.1)
*   **失效机理**：主核 Linux 上的 `ppe_system` 进程由于空指针、栈溢出或 OOM 被杀，导致主核无法对从核下发报警控制字，从核若锁死在旧状态可能导致漏报。
*   **管控策略**：主核发送心跳，从核计数。主循环周期 500ms，2s 无响应（连续 4 次 miss）从核自动判定主核宕机。从核主动拉高蜂鸣器，停止给硬件看门狗 `FWDT0` 喂狗，超时 10s 后物理复位飞腾派芯片。
*   **验证方法**：发送 `kill -STOP` 挂起主进程，验证从核在 2s 内响起警报，并在后续看门狗超时后系统冷重启。

### 2.2 应对【应用进程不响应】：AMP 物理隔离与硬中断接管 (7.2.2)
*   **失效机理**：主核 Linux 遭遇死锁或高负载死机，内核调度线程无法响应。
*   **管控策略**：基于飞腾派的异构多核物理隔离，Core 1 从核裸机不受主核 Linux 内核的任何状态影响。火焰传感器引脚绑定到从核物理 EXTI 中断上。
*   **验证方法**：使用 `stress-ng` 打满主核算力使其假死，手动触发火焰传感器，验证蜂鸣器依然能在微秒级内拉高响应。

### 2.3 应对【传感器硬件损坏】：传感器极值校验与离线隔离 (7.2.3)
*   **失效机理**：温湿度探头（AHT20）由于现场震动脱落，或有害气体传感器（MQ-2）损坏，上报全零或异常突变数据。
*   **管控策略**：从核驱动加入物理极值校验（如温度高于 80°C 或突变量超 15°C/s 判定为异常值）。启动时加入 100ms 超时限制，防止缺失探头挂死系统。
*   **验证方法**：物理断开 I2C SDA 引脚，观察从核输出 `Skipping` 并正常启动，主核 UI 面板相应数值框显式变为黄色警告。

### 2.4 应对【非法控制数据异常】：异构通信链路串扰与 RPMsg 帧校验 (7.2.4)
*   **失效机理**：共享内存段在车间强电磁干扰下产生随机翻转，或伪造命令字越权写入。
*   **管控策略**：数据包尾注入 **CRC-8/MAXIM** 校验值。主从接收端重新计算校验和，对不匹配的数据帧做丢弃处理，防止非预期报警。
*   **验证方法**：向控制字符设备 `/dev/rpmsg0` 写入随机乱码，验证从核无异常蜂鸣，且 UI 的 CRC 校验错误计数器累加。

### 2.5 应对【断电数据保存失败】：告警证据原子写入防损毁 (7.2.5)
*   **失效机理**：违规抓图在写入磁盘文件期间，现场设备突然断电，导致磁盘上留有一张 0 字节或半截损坏的不可读 JPEG。
*   **管控策略**：`io_node` 在写盘时先保存为 `xxx.jpg.tmp`，在文件完全编码落盘并调用 `fsync` 后，再执行 Linux 文件系统的原子重命名操作：`rename("xxx.jpg.tmp", "xxx.jpg")`。
*   **验证方法**：在触发违规存图的瞬间直接拔掉开发板电源，重新开机后验证抓拍目录中不存在任何损坏的残缺图。

### 2.6 应对【关键功能部件损坏】：AI 权重损坏与备用模型回退 (7.2.6)
*   **失效机理**：YOLO 权重文件（`model1_int8.bin`）在 SD 卡中发生物理损坏或被意外删改。
*   **管控策略**：AI 推理线程在启动时执行模型合法性与校验和检测，一旦加载失败，优雅退出当前 AI 推理主环，并向从核发送 `DEVICE_CORE_SHUTDOWN`，防止以错误状态指导物理外设。
*   **验证方法**：人为删除或清空模型权重文件，启动系统，验证其优雅报错退出且界面指示灯变红。

### 2.7 应对【安全数据非法访问】：权限隔离与属主控制 (7.2.7)
*   **失效机理**：非授权用户通过 SSH 或本地终端越权删除、修改违规抓拍存图，导致取证证据丢失。
*   **管控策略**：违规抓拍输出目录 `violations_data/` 使用 `chmod 700` 进行严格的读写执行限制，并设定其属主为 `root`。普通用户无读写权。
*   **验证方法**：切换普通用户 `user` 访问抓拍目录，验证报错 `Permission denied`。

### 2.8 应对【安全功能失效】：内核信号量捕获与异常退出复位 (7.2.8)
*   **失效机理**：主程序遭遇 `Ctrl+C` 强退或因其他非致命故障崩溃退出，底层物理蜂鸣器仍维持触发态发生啸叫。
*   **管控策略**：主程序在 `main.cpp` 中通过 `sigaction` 捕获 `SIGINT`、`SIGTERM` 等内核退出信号，在退出前强制下发声光清零命令。
*   **验证方法**：在蜂鸣器鸣叫时，在控制台按下 `Ctrl+C`，验证主程序退出且蜂鸣器瞬间关闭。

### 2.9 应对【潜在系统风险】：存储满载监控与防洪自清洁 (7.2.9)
*   **失效机理**：高频抓拍存图使 SD 卡存储完全写满，导致 Linux 系统分区锁死，业务中断。
*   **管控策略**：`io_node` 写盘前调用 `statvfs` 读取剩余扇区。当分区整体占用率突破 **85%** 阈值时，自动触发自清洁：按时间戳从小到大升序排序，清除最旧的 1500 张历史抓拍图片。
*   **验证方法**：向磁盘写入大文件使分区超 85%，触发一次违规，验证成功自动清除旧图腾出空间。

### 2.10 应对【外设不可逆物理损坏】：硬件探伤诊断机制 (7.2.10)
*   **失效机理**：火焰传感器引脚或蜂鸣器物理烧毁，完全失去灾情监测与干预能力。
*   **管控策略**：从核通过定时读取引脚状态（开路状态时 GPIO 具有特定的阻抗电平跳变特性）进行外设探伤。主核检测到从核探伤错误码后，界面徽章变为黄色警告。
*   **验证方法**：物理拔掉传感器供电线，观察主核大屏“外设状态”红黄闪烁。
