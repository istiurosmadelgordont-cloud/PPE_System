# PPE 智能监控系统 — 安全可靠性设计说明

> 飞腾派 E2000Q 异构多核平台 | 双生序章团队

## 1. 设计理念

本系统的安全可靠性设计遵循以下核心原则：

### 1.1 异构隔离 (Heterogeneous Isolation)

```
┌──────────────────────────────────┐    ┌──────────────────────────┐
│        Linux 域 (Core 0/2/3)      │    │  Bare-Metal 域 (Core 1)   │
│                                    │    │                          │
│  ┌─────────┐  ┌────────────────┐  │    │  ┌──────────────────┐   │
│  │ Qt GUI   │  │ NCNN AI 推理    │  │    │  │ GPIO 中断处理     │   │
│  │ Core 0   │  │ Core 2+3       │  │    │  │ 蜂鸣器控制        │   │
│  └─────────┘  └────────────────┘  │    │  │ 看门狗             │   │
│        │              │            │    │  └──────────────────┘   │
│        │    RPMsg (共享内存)       │◄──►│      OpenAMP             │
│        ▼                          │    │                          │
│  ┌──────────────────────────┐    │    │  ✅ 独立于 Linux         │
│  │ IO 存储 / DeepSeek API   │    │    │  ✅ 无 OS 调度开销       │
│  └──────────────────────────┘    │    │  ✅ 微秒级中断响应       │
└──────────────────────────────────┘    └──────────────────────────┘
```

**安全意义**: 从核运行于裸机环境，完全独立于 Linux 内核。即使 Linux 内核 panic、OOM、或主进程段错误，从核的传感器监控和蜂鸣器控制仍可独立运行。这是利用飞腾 E2000Q 多核异构架构实现的**物理级故障隔离**。

### 1.2 失效即安全 (Fail-Safe)

当系统检测到异常状态时，自动切换到最安全的默认状态：

| 异常场景 | 安全动作 | 实现位置 |
|---------|---------|---------|
| 主核崩溃 | 关闭蜂鸣器 | 从核看门狗 |
| RPMsg 断连 | UI 显示告警 | 心跳超时 |
| 数据损坏 | 丢弃数据包 | CRC8 校验 |
| 磁盘满 | 删除最旧文件 | 磁盘自愈 |
| 模型缺失 | 安全退出 | 加载检查 |
| API 不可达 | 使用预设建议 | 降级策略 |
| 外设损坏/断线 | UI 提示外设故障，万用表辅助测试阻抗与引脚电平 | 裸机环路自检 / 万用表测量 |

### 1.3 非对称防护 (Asymmetric Defense)

系统在不同方向施加不同强度的防护：

**触发要"慢"**:
- 火警确认需连续 3 次信号 (2 秒窗口内)
- 防止电磁干扰毛刺导致误报

**解除要"更慢"**:
- 火警解除需沉默 3 秒
- 防止信号间隙导致红绿闪烁

## 2. 双向监督架构

```
       主核 (Linux)                    从核 (Bare-Metal)
       ┌─────────┐                    ┌─────────────┐
       │ rx_task  │ ──── 心跳 ────►   │ endpoint_cb │
       │          │ ◄── ACK ─────    │             │
       │ 15s超时→ │                    │ 10s超时→    │
       │ 降级告警  │                    │ Fail-Safe   │
       └─────────┘                    └─────────────┘
```

- **主核监督从核**: 5 秒一次心跳，15 秒无回复判定从核离线。
- **从核监督主核**: 看门狗计数器，~10 秒无心跳自动进入安全状态并切断报警发声。
- **双向 CRC 校验**: 所有跨核数据包都携带 CRC8 校验码。
- **双向数据帧字节对齐**: 主从两侧的数据帧结构体定义统一采用 `#pragma pack(1)` 强行对齐，并且心跳与控制包的传输尺寸在双侧精确统一对齐为 262 字节，防止因结构体末尾的空洞或长度偏差导致校验失败，避免了频繁误判重启。

## 3. 通信安全设计

### 3.1 协议结构

```c
#pragma pack(push, 1)
typedef struct {
    uint32_t command;           // 命令字
    uint16_t length;            // 数据长度
    char     data[256];         // 数据负载
    uint8_t  crc8;              // CRC-8/MAXIM 校验码
} data_packet;
#pragma pack(pop)
```

### 3.2 CRC-8/MAXIM 算法

- 多项式: 0x31 (x⁸ + x⁵ + x⁴ + 1)
- 初始值: 0xFF
- 校验范围: command + length + data (不含 crc8 自身)
- 计算复杂度: O(n), 适合裸机实时环境

### 3.3 数据包收发流程

```
发送方:                              接收方:
  填充 command/length/data           读取数据包
  计算 CRC8                          计算 CRC8
  填入 pkt.crc8                      比较 expected vs pkt.crc8
  write(rpmsg_fd, &pkt)              匹配 → 正常处理
                                     不匹配 → 丢弃 + 计数器++
```

### 3.4 跨核通信热插拔与防卡死保护

- **防止内核死锁 (D-state Block)**：主核在执行重连检测时，会首先调用 `is_slave_core_running()` 审计 remoteproc 的物理状态。若从核被关闭或掉电，则重连线程休眠退避，绝不调用 `ioctl(RPMSG_CREATE_EPT_IOCTL)`。该设计消除了 Linux 进程在等待不存在的从核硬件端点时进入“不可中断睡眠(D状态)”死锁导致整机卡死的问题。
- **动态通道自适应自愈 (Channel Hotplug)**：在从核被反复关闭和重启时，Linux 字符设备驱动不会主动回收并重置端点，而是顺延注册 `/dev/rpmsg0` ~ `/dev/rpmsg6` 等占位节点。主程序引入动态通道匹配机制，利用 `glob` 正则扫描所有活跃节点并排序，永远自适应绑定最新的活动物理节点（如 `/dev/rpmsg6`），实现了从核在无数次热启动、异常崩溃重拉后主核均能毫秒级重联，确保了警报信道的高实时性与高强韧度。

## 4. 降级策略

当系统部分功能不可用时，采用优雅降级而非全面停机：

| 降级层级 | 触发条件 | 系统行为 |
|---------|---------|---------|
| **Level 0 (正常)** | 所有组件正常 | 全功能运行 |
| **Level 1 (轻度)** | DeepSeek API 不可达 | AI 建议使用预设文本，其他功能不受影响 |
| **Level 2 (中度)** | RPMsg 断连 | UI 显示告警，AI 推理和 IO 存储正常 |
| **Level 3 (重度)** | 主核崩溃 | 从核独立运行，蜂鸣器进入安全状态 |

## 5. 与飞腾芯片安全特性的结合

1. **FTC310 多核隔离**: 利用 remoteproc 机制将安全关键功能（传感器 + 蜂鸣器）部署到独立核心，避免 Linux 故障域扩散
2. **PSCI 电源管理**: 从核通过 `FPsciCpuOff()` 安全关闭，避免异常状态残留
3. **GPIO 中断优先级**: 火焰传感器设置为最高优先级 (Priority 0)，保证微秒级响应
4. **共享内存保护**: CRC8 校验防止共享内存区域数据损坏

## 6. 故障注入（FIT）自愈验证

本系统在 `tests/` 目录中配备了 5 套自动化故障注入脚本，用于在验证期间人工触发系统性的硬核故障，以实证安全防线的有效性：

- **`fit_rpmsg_disconnect.sh` (从核通信断连测试)**：断连后主核守护线程秒级感知并挂起 ioctl 通信（防死锁），UI 连接状态灯同步变红；从核因关停停止喂狗，10秒超时触发物理 WDT0 看门狗复位，整机冷重启自愈。
- **`fit_main_crash.sh` (主程序崩溃死机测试)**：在警报期间杀死主程序，从核心跳超时后在 10s 内释放外设电源（关闭蜂鸣器），进入 Fail-Safe 静默状态，随后自断喂狗触发看门狗硬件整机重启。
- **`fit_crc_corrupt.sh` (信道数据损坏防磁测试)**：持续灌入随机脏字节，两端通过 CRC8 校验（多项式 `0x31`）全量截获丢弃脏包。主从核无误动，UI 的 CRC 错误计数器动态累加。
- **`fit_model_missing.sh` (AI模型损坏完整性修复测试)**：人为删除核心模型，程序拦截启动，自动触发 `pull_model.sh` 执行网络热恢复或本地备份镜像覆盖自愈（已加固 `-s` 大小判定防 0 字节文件污染）。
- **`fit_deepseek_offline.sh` (API顾问断网熔断测试)**：拔除网线后，网络请求在异步子线程中运行，UI 与 YOLO 推理 100% 流畅；10秒超时熔断后自动无缝降级加载本地高安全字典。

## 7. 总结

本系统的安全可靠性设计充分利用了飞腾 E2000Q 的异构多核架构优势，实现了：

- ✅ 物理级故障隔离（从核独立于 Linux）
- ✅ 双向心跳监督（主核监督从核 + 从核监督主核）
- ✅ 通信数据完整性校验（CRC8）
- ✅ 失效即安全（Fail-Safe）设计
- ✅ 多级优雅降级策略
- ✅ 完整的 FIT 故障注入测试覆盖
